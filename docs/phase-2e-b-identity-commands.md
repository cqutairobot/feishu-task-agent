# Phase 2E-B：群内身份绑定命令

本阶段只处理明确 `@机器人` 的身份管理命令。普通群聊继续正常入库，
不会被命令解析器处理。私聊绑定暂不启用，因为私聊消息无法唯一确定别名所属的群。

## 飞书权限

机器人回复绑定结果需要在飞书开发者后台申请“以应用的身份发消息”权限，
权限标识通常为：

```text
im:message:send_as_bot
```

新增权限后，需要创建并发布新的应用版本，并完成企业管理员审批。

## 本人绑定

成员在目标群发送：

```text
@任务机器人 绑定姓名：王哈
```

也接受更自然的等价写法：

```text
@任务机器人 我的姓名 王哈
@任务机器人 我的姓名：王哈
```

机器人使用消息发送者自身的 `open_id` 进行绑定，不从姓名猜测用户身份。
同一成员在同一群内只能保留一个当前姓名。再次绑定会直接替换当前姓名，并
立即释放旧姓名；旧姓名不会继续用于负责人匹配。

预期回复：

```text
✅ 姓名绑定成功

本群姓名：王哈
以后涉及“王哈”的任务将关联到你。
```

## 查询本人绑定

```text
@任务机器人 我的姓名
```

## 管理员代绑定

先在本机 `.env` 配置允许执行代绑定的用户 Open ID：

```dotenv
FEISHU_IDENTITY_ADMIN_OPEN_IDS=ou_xxx
```

多个管理员使用英文逗号分隔。管理员随后可以在群内发送：

```text
@任务机器人 绑定成员 @目标成员 为 王政
```

机器人只接受通过飞书 `@` 选择的目标成员，并从事件的 `mentions` 数据中读取
目标 `open_id`。目标成员应当已经在群里发送过至少一条被本程序保存的消息。

## 安全规则

- 机器人必须是消息开头的第一个明确 `@` 对象。
- 本人绑定只能修改消息发送者自己的群内姓名。
- 管理员代绑定必须通过管理员 Open ID 白名单。
- 同一个姓名在同一个群内只能对应一个成员，冲突时拒绝修改。
- 同一个成员在同一个群内只能有一个姓名，改名后旧姓名立即释放。
- 同一个姓名可以在不同群内对应不同成员。
- 重复投递的同一飞书事件不会重复执行命令或重复回复。
