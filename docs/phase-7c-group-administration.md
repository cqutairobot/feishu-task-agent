# Phase 7C：群管理员自助配置与权限闭环

Phase 7C 让机器人加入新群后不再依赖代码里预置管理员，同时保证所有权限
始终以飞书当前群成员和当前群主为准。

## 群主初始化与恢复

群主在群内发送以下命令，且必须把机器人放在消息开头：

```text
@机器人 初始化本群
@机器人 接管本群
```

- `初始化本群` 只用于还没有任何任务管理员的新群；已有管理员时不会覆盖。
- `接管本群` 用于群主更换、原管理员离群或群主需要恢复自身权限的情况；
  它只给当前群主本人增加权限，不会静默删除其他管理员。
- 每次执行都会实时向飞书重新获取完整成员列表和当前群主。无法核验时拒绝
  写入，不使用过期缓存作授权依据。
- 机器人提及不可省略，普通聊天中的同名文字不会触发管理员变更，也不会送
  给任务识别模型。

静态 `FEISHU_ALLOWED_CHAT_IDS` 可以继续保护已有部署。名单之外的新群只接受
上述显式初始化/接管命令；初始化成功后，以数据库中的群级管理员记录作为
动态准入依据，后续普通群消息无需再修改 `.env`。未初始化的其他群仍被忽略。

## 后台管理员管理

已认证的群管理员进入“群管理员与审计”页面后，可以：

- 查看当前飞书群主、当前有效成员和任务姓名绑定；
- 把当前群成员设为本群管理员；
- 撤销本群管理员；
- 查看初始化、接管、后台授权、后台撤权和成员同步撤权记录。

每次网页写入前，服务端都会强制刷新飞书成员目录并重新认证会话。浏览器不
提供或决定操作人 Open ID；服务端只使用 HttpOnly 登录会话内已验证的身份。
写请求必须来自配置的前端 Origin。授权目标必须仍是该群成员，管理员权限不
会跨群继承，接口和查询也都按精确 `chat_id` 校验。

成员列表同时展示飞书当前名称与群内任务姓名，避免飞书账号名称和自然语言
任务别名不一致时误撤权或误移除成员。

成员权威离群时，其当前任务姓名会自动释放；新成员的身份绑定命令会先强制
同步飞书目录，因此可以立即复用该姓名。历史任务、负责人、消息证据和通知
均使用原有快照，不会被改名或转移给新成员。

人工操作不能撤销最后一名管理员。若确实没有管理员，当前飞书群主仍可通过
“接管本群”恢复，不需要本地修改数据库。

## 离群、群主转移与会话

一次成功的完整成员同步会原子地更新成员和群主状态。已经离群的管理员会被
自动撤权，并写入来源为 `membership_sync` 的审计记录。若其已不再管理任何群，
现有管理后台会话同时失效；若仍管理其他群，会话可继续使用，但无权再访问本
群。同步失败时不会根据不完整数据撤权。

飞书群主转移会在下一次完整同步后更新。新群主随后可以使用“接管本群”。
目录通常随群消息按缓存周期刷新。进入或刷新后台成员页、管理员写入和群主
命令都会强制实时刷新；成员页同步后会再次校验登录会话，再按顺序读取最新
成员和撤权审计。

## 自动化验收

验收覆盖：群主与非群主命令、重复初始化、群主接管、飞书核验失败、名单外
新群动态准入、跨群隔离、非成员授权拒绝、最后管理员保护、管理员增删 HTTP
接口、Origin 与会话认证、成员与审计页面读取、离群自动撤权和会话失效。

完成实现时的全量自动化结果为 408 项 Python 测试通过；管理前端 lint、生产
构建和服务端渲染测试全部通过。

## 真实飞书验收

真实新群已完成以下闭环：非群主初始化被拒绝、群主初始化、后台增加与撤销
管理员、最后管理员保护、群主转移后接管、成员离群自动撤权与会话失效、离群
成员任务姓名释放、新成员复用姓名、名单外动态群消息识别、任务物化、私聊任务
列表、截止提醒、私聊自然语言完成、剩余提醒取消、另一位管理员状态通知以及
后台状态同步。

验收期间发现并修复了“任务创建时已经进入 24 小时区间，会依次补发 24 小时
和 72 小时提醒”的问题。原因是被更紧急提醒取代的旧档位在下一轮全量同步时
被重新激活。现在 `superseded_by_*` 取消记录在同一提醒计划中保持终态；真实
回归结果为只发送一条 24 小时提醒，72 小时档保持取消。
