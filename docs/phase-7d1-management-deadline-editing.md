# Phase 7D-1：管理后台修改截止时间

Phase 7D-1 允许本群管理员在任务详情中直接修改 `todo` 或 `overdue` 任务的
截止时间。页面统一按北京时间（UTC+8）输入和展示；服务端拒绝无时区、过去、
未变化或终态任务的修改。

## 权限与事务

- 浏览器只提交新时间和一次性幂等请求 ID，不提交或决定操作人 Open ID。
- 服务端从 HttpOnly 会话恢复操作人，强制刷新当前飞书群成员，再次认证会话，
  并校验操作人仍是精确 `chat_id` 下的管理员。
- 任务更新、`management_page` 生命周期审计和提醒计划重排在同一个 SQLite
  事务内完成，任一环节失败都会整体回滚。
- 相同请求 ID 的完全一致重试返回原结果；同一请求 ID 携带不同任务或时间时
  拒绝执行。

迁移 `20260823_0020` 为生命周期事件增加
`trigger_management_request_id`，并把 `management_page` 纳入受约束的触发
来源。后台操作不会伪装成飞书消息或卡片回调。

## 页面行为

只有可操作任务会显示“修改截止时间”。保存成功后，页面立即刷新任务详情、
任务列表、统计数据和群摘要；生命周期与提醒记录可在同一详情抽屉中查看。

后台改期沿用现有通知 Worker。负责人会收到私聊改期通知，其他管理员也会
收到通知；如果同一成员同时是负责人和管理员，同一事件只发送一条与负责人
角色对应的通知，避免重复刷屏。

## 验收

自动化覆盖精确群权限、Origin、飞书成员重新核验、未来时间校验、状态校验、
跨群拒绝、幂等重放冲突、生命周期来源、提醒重排以及重叠角色通知去重。

真实验收使用“管理员测试”群中的 `T-IB`，从任务详情把截止时间调整到新的
北京时间，再核对详情、列表、提醒计划、生命周期审计和私聊通知。
