# Phase 7D-2：管理后台纠正标题与负责人

Phase 7D-2 在任务详情中增加“修改任务标题”和“调整负责人”。它用于纠正模型
识别错误或群聊后续明确变更，不创建另一条重复任务。

## 业务规则

- 只允许修改 `todo` 或 `overdue` 任务；已完成、已取消等终态任务保持不可变。
- 标题会统一 Unicode 与空白，不能为空，最长 200 个字符。
- 一个任务必须保留 1 至 20 名负责人；第一位是主负责人，其余是共同负责人。
- 候选人必须是飞书实时核验后仍在本群的成员，并且已经在本群绑定任务姓名。
  离群成员、其他群成员、未绑定姓名的成员都不能被选中。

## 权限、幂等与事务

浏览器只提交新标题或负责人 Open ID 列表，以及一次性请求 ID。服务端从
HttpOnly 会话恢复操作人，强制刷新飞书成员，重新校验其仍是该 `chat_id` 的
管理员，再把 Open ID 转换为当前可信的姓名绑定。

相同请求 ID 与相同内容可安全重试；若复用请求 ID 改写任务、动作或内容，
服务端拒绝执行。任务内容、负责人顺序、主负责人镜像字段、生命周期审计、
提醒取消或重排均在同一个 SQLite 事务中提交，失败时整体回滚。

标题修改记录 `rename` 生命周期事件；负责人修改记录 `reassign` 事件。两者的
触发来源均为 `management_page`，不会伪装成群消息、私聊或卡片操作。Phase
7D-2 复用迁移 `20260823_0020`，不新增数据库迁移。

## 页面和通知

保存成功后，任务详情、任务列表、统计数据和群摘要同步刷新。负责人编辑器明确
标出主负责人和共同负责人；没有任务姓名绑定的成员会显示但不可选择。

标题或负责人发生变化后沿用现有私聊通知 Worker。操作人不接收自己触发的
重复通知；同一收件人同时具备负责人和管理员角色时，每个事件只生成一条通知。
负责人调整后，旧提醒计划被取消，新负责人按照当前截止时间获得新的提醒计划。

## 验收

自动化覆盖标题规范化、长度限制、当前群成员与姓名绑定校验、共享负责人顺序、
跨群和离群成员拒绝、幂等重放、生命周期前后值、提醒重排、Origin 与精确群
管理员权限。完整 Python 回归共 413 项，前端静态检查、生产构建与页面契约
测试均通过。
