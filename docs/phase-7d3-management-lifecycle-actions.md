# Phase 7D-3：管理后台生命周期操作

Phase 7D-3 允许本群管理员在任务详情中明确执行三种终态操作：标记完成、取消
任务、撤销误识别。它面向 `todo` 和 `overdue` 任务；终态任务不能再次修改，
`pending` 待确认任务的审核留在后续独立阶段处理。

## 操作含义

- **标记完成**：状态变为 `done`，记录完成时间。
- **取消任务**：状态变为 `cancelled`，表示真实任务不再需要执行。
- **撤销误识别**：状态同样变为 `cancelled`，但生命周期动作记录为
  `invalidate`，明确区分“真实任务取消”和“机器人识别错误”。

页面在提交前显示二次确认。三种操作都不可通过页面恢复，避免误触后静默改写
历史；若确实误操作，可由后续恢复方案依据审计记录处理。

## 安全与一致性

浏览器只提交 `complete`、`cancel` 或 `invalidate` 之一和一次性请求 ID，不提交
操作人身份。服务端从 HttpOnly 会话恢复操作人，强制刷新飞书成员，再校验其仍
是精确 `chat_id` 下的管理员。

任务状态、完成或取消时间、`management_page` 生命周期审计以及未发送提醒取消
在同一个 SQLite 事务中提交。相同请求可安全重试；复用请求 ID 执行另一动作或
修改另一任务会被拒绝。Phase 7D-3 复用迁移 `20260823_0020`，不新增数据库
迁移。

## 通知

现有任务通知 Worker 会按动作通知相关负责人和其他管理员，同时跳过操作人。
一名成员同时是负责人和管理员时，每个生命周期事件只生成一条角色明确的通知。
终态写入后，该任务所有未发送截止提醒都会被取消。

## 验收

自动化覆盖三种动作、非法动作拒绝、Origin、精确群管理员权限、终态拒绝、幂等
重放和冲突、生命周期来源以及提醒取消。完整 Python 回归共 415 项，前端静态
检查、生产构建和页面契约测试均通过。
