# Phase 7D-5A：管理员手动补建任务

状态：已完成。实现、自动化回归和真实管理后台与飞书私聊验收均通过。

## 目标

当模型完全漏识别一项任务、数据库里没有对应记录时，本群管理员可以从当前群的
任务总览手动补建。该入口用于异常恢复，不替代模型识别，也不制造虚假的模型
证据。

## 业务规则

- 只有当前 `chat_id` 的持久管理员可创建。
- 创建前实时刷新飞书群目录；权限失效时请求失败关闭。
- 标题必填，长度 1–200；说明可选，最长 2000；截止时间可选且必须晚于创建
  时间。
- 必须选择 1–20 名当前群内仍有效、已绑定任务姓名的成员；顺序保留，第一位是
  兼容旧字段的主负责人。
- 创建后直接进入 `todo`，置信度固定为 `1.0`，并使用现有稳定任务编号。
- 一个多人任务只产生一条任务记录和一个编号。
- 有截止时间时，每位负责人各生成四个持久提醒；无截止时间时不生成四阶段提醒，
  后续由现有缺失截止时间策略追问。
- 每位负责人各生成一次 `task_created_assignee` 私聊通知。
- 浏览器提供 128 位请求 ID；服务器以该 ID 幂等处理。相同内容重试返回原任务，
  不重复通知或提醒；同 ID 携带不同内容会被拒绝。

## 数据与审计

迁移 `20260823_0023` 新增 `task_creation_events`：

- 每个手动创建任务恰好一条创建事件；
- 保存操作管理员、请求 ID、标题/说明/截止时间快照和有序负责人快照；
- 来源固定为 `management_page`；
- 不创建 `detection_runs`、`task_sources` 或 `task_evidence`。

任务、负责人、创建事件、提醒计划和负责人通知在同一数据库事务内提交；任一步骤
失败都不会留下半条任务。
