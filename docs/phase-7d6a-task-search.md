# Phase 7D-6A：任务编号与文本搜索

状态：已完成实现、自动化校验与真实管理后台验收。

## 目标

任务数量增加后，管理员可以在当前群快速定位一条任务。编号搜索必须精确、稳定并
保持群隔离；没有输入编号时，仍可以按标题或说明查找。

## 业务规则

- 支持完整任务编号，例如 `T-1A`，以及私聊中使用的短编号，例如 `1A`。
- 合法编号按任务主键精确匹配，不把编号当作标题模糊匹配。
- 标题和说明使用不区分大小写的包含搜索；搜索词前后空白会被清理。
- 所有搜索都叠加当前 `chat_id` 和当前管理员权限；其他群的合法编号返回空结果。
- 不存在或校验失败的编号不会泄露其他群任务；它会按普通文本搜索处理，除非没有
  标题或说明匹配。
- 搜索词显示在结果摘要中，清空后恢复当前状态筛选；搜索词写入 URL，刷新页面后
  自动恢复。

## 接口与实现

管理 API 继续使用：

```text
GET /api/chats/{chat_id}/tasks?query=T-1A&status=todo
```

读模型在授权后先构造 `Task.chat_id == chat_id` 条件，再追加编号或文本条件；编号
解析使用稳定任务编号校验函数，不依赖任务标题或可变内容。当前 API 已返回
`total_count`、`limit`、`offset`，但页面分页控件留在 7D-6B。

## 自动化校验

- 完整编号和短编号匹配同一任务。
- 另一群的合法编号在当前群查询返回空结果。
- 标题/说明模糊搜索和既有状态、负责人、截止时间筛选保持兼容。
- 管理 HTTP API、前端 lint、生产构建和页面渲染契约测试通过。

## 真实验收

1. 打开当前群管理后台，在搜索框输入一个已知任务的完整编号，例如 `T-1A`，提交。
2. 预期只显示这一条任务，结果摘要显示搜索词和结果数。
3. 清空搜索，确认任务列表恢复当前状态筛选。
4. 输入同一任务的短编号 `1A`，确认结果相同。
5. 输入任务标题中的关键词，确认可以匹配标题或说明。
6. 刷新页面，确认搜索词仍在，结果不回到默认列表。
7. 如果已有第二个群，输入第二个群任务的编号，当前群应显示“没有任务”，不能看到
   其他群数据。
