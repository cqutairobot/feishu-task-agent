# Phase 7E-1：每群基础设置

## 目标

为每个精确 `chat_id` 提供可持久化、可审计的基础识别设置。该阶段只处理
自动任务识别开关和自动进入 `todo` 的置信度门槛，不改变提醒时间和管理员通知
策略。

## 设置

- `detection_enabled`：默认开启。关闭后仍保存新消息，但不会把消息加入检测队列。
- `auto_todo_confidence`：默认 `0.85`，范围 `0..1`。检测结果低于该群门槛时进入
  `pending`，达到门槛时进入 `todo`。
- `timezone`：固定为 `Asia/Shanghai`，当前产品仅在中国区使用，不提供修改入口。

所有设置都以 `chat_id` 为主键，群 A 的设置不会影响群 B。更新必须由该群当前
管理员完成，并写入设置前后值、操作人和时间的审计记录。

## 管理 API

```text
GET  /api/chats/{chat_id}/settings
GET  /api/chats/{chat_id}/settings/events?limit=20
POST /api/chats/{chat_id}/settings
```

写入请求只允许以下字段：

```json
{
  "detection_enabled": false,
  "auto_todo_confidence": 0.95
}
```

## 验收步骤

1. 在管理后台打开“群设置”，确认默认开关为开启、门槛为 85%、时区为
   `Asia/Shanghai`。
2. 把门槛调到 95%并保存，刷新页面确认仍为 95%，并确认设置审计出现记录。
3. 关闭自动任务识别并保存；在该群发送一条普通文本，确认消息仍进入数据库，
   但不产生新的检测队列任务。
4. 重新开启识别。
5. 切换到另一个群，确认该群仍保持自己的默认或已配置值，不继承前一个群的设置。
6. 将测试群门槛恢复为 85%，为后续阶段准备。

自动化覆盖：设置仓库默认值、管理员授权、非法门槛、审计记录、跨群隔离、管理
HTTP API、前端 lint、生产构建和页面契约。
