# Phase 7E-2A：每群提醒阶段开关

## 范围

本阶段只允许当前群管理员分别开启或关闭四类负责人截止提醒：

- 提前 72 小时
- 提前 24 小时
- 截止当天
- 任务逾期

设置严格按 `chat_id` 隔离。它不改变新任务通知、生命周期通知或无截止日期升级
通知，也不提供自定义提前量、提醒时间或管理员通知对象。

## 数据与事务规则

- 迁移 `20260824_0027` 在 `chat_settings` 增加四个布尔字段，默认全部开启。
- 修改设置要求操作者仍是当前群管理员，并把前后值、操作者和时间写入
  `chat_setting_events`。
- 保存设置时，在同一数据库事务内重新同步本群全部 `todo`、`overdue` 任务的提醒
  计划。
- 关闭阶段只取消对应的 `scheduled` 或 `leased` 记录，取消原因为
  `reminder_stage_disabled`。
- 已发送提醒及其飞书消息 ID 永久保留，不撤回、不改写，也不会因重新开启而重复发送。
- 重新开启阶段时，尚未发送且仍有效的同一提醒记录可以安全恢复；唯一约束保证不会
  生成重复计划。

## 自动化验证

- 默认四个阶段全部开启。
- 群 A 修改开关不会改变群 B。
- 非管理员、非布尔输入和非法跨群访问被拒绝。
- 关闭阶段会取消相应未发送计划；重新开启会恢复原计划且不产生重复行。
- 已发送历史在关闭、重新开启后保持 `sent`。
- 设置 API、审计结果和管理前端字段保持一致。
- 完整 Python 回归 439 项通过；管理前端 lint、生产构建和 2 项页面契约测试通过。

## 真实验收

### 1. 页面、持久化和群隔离

1. 从飞书私聊机器人发送“管理后台”，进入“群设置”。
2. 在群 A 关闭“提前 72 小时”和“任务逾期”，保存并刷新页面。
3. 确认两个开关仍关闭，右侧设置审计出现本次修改。
4. 切换到群 B，确认群 B 的四个开关没有随群 A 改变。

### 2. 实际提醒计划

1. 在群 A 保持“提前 72 小时”关闭，其他阶段开启。
2. 创建一项截止时间约为当前时间后 48 小时的测试任务。
3. 负责人应收到“新任务”私聊，但不应收到“提前 72 小时”截止提醒。
4. 回到群 A 设置，重新开启“提前 72 小时”并保存。
5. 因该阶段的计划时间已经到达，Reminder Worker 应很快只发送一次 72 小时提醒。
6. 再次保存或刷新页面不应重复发送同一阶段提醒。

验收后可取消测试任务，并把四个开关恢复到实际希望使用的状态。
