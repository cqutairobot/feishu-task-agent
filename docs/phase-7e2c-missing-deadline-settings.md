# Phase 7E-2C：每群无截止日期提醒规则

## 范围

当前群管理员可以独立配置：

- 是否私聊负责人补充截止时间，默认开启。
- 任务创建后多少小时提醒负责人，范围 `1..720`，默认 24 小时。
- 是否在负责人仍未设置时私聊本群管理员，默认开启。
- 任务创建后多少小时升级管理员，范围 `2..2160`，默认 72 小时。

管理员升级时间必须晚于负责人提醒时间。系统每个阶段最多向每个有效收件人发送
一次；管理员阶段完成后不再继续追问。

## 数据和队列规则

- 迁移 `20260824_0029` 在 `chat_settings` 增加两个开关和两个小时字段。
- 设置按精确 `chat_id` 隔离并写入现有设置审计。
- Task Notification Worker 每轮同步时读取任务所属群的最新规则。
- 修改时间会更新尚未发送通知的 `scheduled_for` 和 `available_at`，不创建第二套
  通知。
- 关闭阶段会以 `notification_stage_disabled` 取消未发送通知；重新开启会复用该
  记录并清理旧租约和错误状态。
- 已发送通知永久保留，不撤回、不重发。
- 通知文案根据任务创建时间与该条通知的实际计划时间动态显示分钟、小时或天数，
  不使用固定的“1 天/3 天”描述。
- 任务设置截止时间、完成或取消后，仍按既有规则取消尚未发送的缺失截止日期通知。
- 负责人变化、管理员变化和成员权限仍按当前群实时校验。

## 自动化结果

- 默认 24/72 小时、两个开关、合法更新、非法类型、非法范围和非法顺序均已覆盖。
- 时间重排、阶段关闭、重新开启、记录复用和已发送历史保护均已覆盖。
- 多负责人、全部本群管理员、管理员撤权及跨群隔离的既有回归保持通过。
- 完整 Python 回归 445 项通过；管理前端 lint、生产构建和 2 项页面契约测试通过。

## 真实验收

### 页面和隔离

1. 进入群 A 的“群设置”，找到“未设置截止时间”。
2. 将负责人提醒改为 12 小时、管理员升级改为 36 小时并保存。
3. 刷新后确认数值保留，设置审计显示 `负责人+12h/管理员+36h`。
4. 关闭负责人提醒，确认负责人小时输入被锁定；重新开启后恢复可修改。
5. 将负责人设为 48、管理员设为 24，页面应禁止保存并提示升级必须更晚。
6. 切换群 B，确认其仍为独立的默认 24/72 小时。

### 真实通知

可使用某个群中一项已经创建超过两小时、仍无截止日期的测试任务：

1. 先关闭管理员升级，只开启负责人提醒，设置为 1 小时并保存。
2. 负责人应很快收到一次“请设置任务截止时间”私聊。
3. 再开启管理员升级并设置为 2 小时，当前群管理员应各收到一次升级私聊。
4. 重复保存相同设置，不应再次发送。
5. 为测试任务补充截止时间或取消任务，并恢复正式的 24/72 小时策略。
