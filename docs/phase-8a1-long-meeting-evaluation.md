# Phase 8A-1：长会议纪要任务识别评估

## 目标

用一条接近真实工作场景的长会议纪要验证当前任务识别链路。纪要同时包含背景讨论、
闲聊、已经完成的历史事项、明确取消的方案、模糊建议，以及单人任务、共同任务、
会议任务和无截止日期任务。

本阶段只评估识别质量，不修改生产模型、不调整提示词，也不把模型比较结果自动写入
真实任务。真实群消息仍由当前生产模型 `qwen3.7-plus` 正常识别和物化。用户决定不
考虑价格更高的模型，因此同一条存储消息改用更便宜的 `qwen3.7-flash` 做只读对照。

## 测试群与前置条件

- 使用群“管理员测试”。
- 王哈、李明在该群的任务姓名均已绑定。
- 自动任务识别保持开启。
- 一次完整发送下面整段纪要，不拆成多条，发送后至少等待 30 秒。

## 预期结果

应该创建 5 条任务：

1. 王哈、李明共同负责“长会议纪要任务抽取验收报告”，截止 `2026-08-26 18:00`。
2. 王哈负责“整理20条误识别聊天样本并标注原因”，截止 `2026-08-27 12:00`。
3. 李明负责“检查任务卡片手机端显示和交互”，截止 `2026-08-27 20:00`。
4. 李明负责“主持识别效果复盘会议”，截止 `2026-08-28 15:00`。
5. 王哈负责“整理 Plus 与 Max 模型成本对比”，截止时间为空。

不应该创建以下任务：

- 重做已经完成的数据迁移。
- 重写管理后台。
- 立即重构 SQLite。
- 研究语音会议转写。
- 购买服务器、迁移数据库、接入日历或决定聚餐地点。

## 模型对照规则

- 生产结果：当前 `qwen3.7-plus` Worker 的真实物化结果。
- 对照结果：对同一条存储消息调用 `qwen3.7-flash` 的批量识别，只读、不写任务。
- 比较任务数量、负责人、共同负责人、标题语义、截止时间、误识别、漏识别、结构化
  输出是否通过本地契约，以及调用耗时和 Token 用量。
- 单次样本不用于直接切换模型；至少完成本阶段全部代表性样本后再做选择。

## 模型成本判断

当前实际生产配置为 `qwen3.7-plus`，并非 `qwen3.7-max`。价格更高的
`qwen3.8-max` 已排除，不再进行真实上下文调用。优先候选改为 `qwen3.7-flash`；它支持
结构化输出和长上下文，公开按量价格显著低于 Plus。

## 真实验收结果

- 原消息完整保存，共 690 个字符；生产 Detection Worker 使用 `qwen3.7-plus` 一次
  成功完成严格 JSON Schema 识别。
- Plus 正确创建 5 条任务：`T-15J`、`T-163`、`T-17L`、`T-185`、`T-19N`；共同
  负责人、四个截止时间和一条无截止日期均符合预期，没有把历史完成、明确取消、
  模糊建议或闲聊物化成任务。
- 六条新任务负责人私聊全部发送成功；`T-19N` 的无截止日期负责人提醒和管理员升级
  按当前群规则排入计划。
- Plus 调用：输入 6799 Token、输出 3096 Token、总计 9895 Token，模型耗时
  53630ms。
- Flash 对同一存储上下文只读识别，同样 5/5 全部正确，严格 JSON Schema 通过；
  输入 6799 Token、输出 5318 Token、总计 12117 Token，端到端耗时 30827ms。
- 按北京公开原价粗略估算，本样本 Plus 约 ¥0.0384，Flash 约 ¥0.0056；Flash 即使
  输出 Token 更多，估算成本仍低约 85%。实际账单以接口所属工作空间和优惠为准。

结论：Phase 8A-1 通过。生产模型暂不切换；Phase 8A 后续只比较价格低于当前 Plus
的模型，`qwen3.7-flash` 为首选候选，并需要更多已验收场景回归后再决定。
