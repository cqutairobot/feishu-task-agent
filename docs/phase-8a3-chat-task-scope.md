# Phase 8A-3：每群任务识别范围

最后更新：2026-08-24（Asia/Shanghai）

## 目标

不同飞书群可以独立决定机器人识别任务的业务范围，不再用一个全局提示词同时满足
工作群和生活群。默认采用更宽泛的生活需求模式。

## 两种模式

### 宽泛任务（`broad`，默认）

工作、科研、学习、会议、生活安排、私人采购和明确跑腿需求都可成为任务。结果仍须
具备明确负责人和可执行动作；普通闲聊、愿望、问题、建议、已经完成或取消的事项不
创建任务。

### 仅工作 / 科研（`work_only`）

只识别工作、科研、学习项目、正式会议和交付物。饮食、私人采购、物品代取和一般
生活跑腿即使有负责人和时间也不创建任务。

## 实现边界

- `chat_settings.task_scope` 保存 `broad` 或 `work_only`，数据库默认值为 `broad`。
- 设置读取、更新和审计均按精确 `chat_id` 及当前管理员权限校验。
- 修改记录写入群设置审计，保存操作人和前后值。
- Detection Worker 在每次构造群聊检测上下文时读取该群当前模式，并把相应规则加入
  单任务和批量任务提示词。
- 不修改生命周期识别规则、置信度门槛或当前生产模型。

## 真实双群验收

1. 在管理后台分别选择两个群，确认默认模式均为“宽泛任务”。
2. 将其中一个群改为“仅工作 / 科研”并保存，刷新后确认设置保留且审计新增记录。
3. 在宽泛群向已绑定成员发送明确的生活任务，应创建任务并私聊负责人。
4. 在仅工作 / 科研群发送同类生活任务，不应创建任务。
5. 在仅工作 / 科研群发送明确的工作任务，应正常创建并私聊负责人。
6. 再次切换两个群，确认设置互不影响。

## 验收结果

2026-08-24 已通过真实双群验收：

- 宽泛模式成功创建明确的生活需求任务并通知负责人；
- 仅工作 / 科研模式正确过滤生活需求；
- 同一仅工作 / 科研群中的明确工作任务正常创建并通知负责人；
- 两群设置持久保存且互不影响。
