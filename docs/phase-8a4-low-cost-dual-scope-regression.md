# Phase 8A-4：低成本模型双范围最终回归

## 目标与安全边界

使用更便宜的 `qwen3.7-flash` 对已经存储并由用户验收过的真实群聊上下文做最终
只读回归。生产配置继续使用 `qwen3.7-plus`；评估不创建 detection job/run、任务、

可重复脚本为 `scripts/phase8a4_dual_scope_eval.py`。必须显式传入
`--execute-real-context` 才允许向模型接口发送存储上下文。

## 样本和判分

共 11 个场景，每个分别使用 `broad` 与 `work_only`，合计 22 次调用：

- 含历史完成、明确取消、闲聊和 5 条行动项的长会议纪要；
- 两人各自完成同一交付物；
- 一句话给两人安排不同任务；
- 两人共同任务；
- 明确时间的会议；
- “周五前”的日历截止；
- 普通询问与身份绑定命令；
- 带饭、买咖啡和送晚饭三类生活需求。

判分同时检查严格 JSON Schema、本地契约、任务数量、单人/共同类型、全部负责人、
截止时间和标题语义关键词。宽泛模式真值为 15 条，工作/科研模式真值为 12 条；后者
还必须过滤全部 3 条生活需求。

## 三轮结果与规则修正

1. 第一轮 21/22。“周五前”在宽泛模式被解析为周五 `00:00`，而产品既定含义是
   周五 `23:59:59`。
2. 明确日历日期取当天结束后，第二轮仍为 21/22。Flash 把“两天内”错误套用日历
   规则，解析为后天 `23:59:59`。
3. 最终规则明确区分：
   - 日历日期或星期且没有时分：截止日 `23:59:59`；
   - 数字时长：从 `reference_time` 精确顺延并保留时分秒。

第三轮最终达到 22/22：

- `broad`：11/11 调用通过，任务 15/15；
- `work_only`：11/11 调用通过，正式任务 12/12，生活需求过滤 3/3；
- 长会议纪要在两种范围下均正确识别全部 5 条；
- 所有调用使用严格 `json_schema`，无结构化契约失败；
- 完整 Python 回归 452 项通过。
