最后更新：2026-08-24（Asia/Shanghai）

## 执行规则

1. 一次只实现一个可独立验收的小阶段。
2. 自动化测试通过后，由用户完成真实飞书或管理后台验收。
3. 用户明确确认预期实现后，才能把该阶段标记为完成并进入下一阶段。
4. 不为测试伪造管理员、负责人或跨群权限；所有授权必须按精确 `chat_id` 校验。
5. 任务、成员、管理员、查询和通知必须保持群隔离。
6. 负责人通知优先私聊，不因私聊失败而在群里泄露或刷屏。
7. 所有写操作必须具备权限校验、幂等键、持久审计和事务一致性。

## 已完成能力

### Phase 1–2：飞书消息与身份

- 无需 `@机器人` 即可监听允许群的普通消息。
- 消息、发送人、群和时间持久保存到 SQLite。
- 每名成员在每个群只有一个任务姓名，每个姓名在该群只属于一人；改名时旧姓名
  立即释放。
- 群成员离群后同步释放姓名占用并撤销其管理员权限。
- 群聊改名、成员变化和群主变化通过飞书目录同步处理。

### Phase 3–4：上下文识别与任务物化

- 采用二十秒滑动窗口收集相关上下文，不按单句逐次调用模型。
- 支持闲聊混入、一句话多任务、多人共同任务和多人各自任务。
- 模型输出经过严格 JSON、成员、Open ID、时间和证据消息校验。
- 检测上下文保留飞书原始 @ 的占位符和目标 Open ID，并把目标姓名规范为该群绑定的
  任务姓名；飞书显示名与任务姓名不同时也不会导致负责人校验失败。有效成员被 @ 后
  发出带明确动作和时间的会议/讨论指令时，按可执行任务识别，不依赖模型猜测目标。
- 检测任务由持久队列处理，支持租约、重试、幂等和审计。
- 任务保存负责人、共同负责人、标题、说明、截止时间、状态、置信度、来源消息与
  稳定任务编号。
- 正常门槛下，高置信度结果进入 `todo`，低置信度结果进入 `pending`。

### Phase 5：提醒与缺失截止时间

- 按 72 小时、24 小时、当天和逾期四个阶段生成持久提醒。
- 完成、取消或延期时原子更新或取消未发送提醒。
- 无截止日期一天后私聊负责人，三天后仍未设置则私聊全部本群管理员，此后停止
  追问。
- 提醒 Worker 与任务通知 Worker 独立运行，均支持失败重试和发送审计。

### Phase 6：任务生命周期与私聊交互

- 负责人可私聊机器人发送任务列表，只查看自己负责的任务。
- 本群管理员可查看本群所有人的任务，不会看到其他群数据。
- 每个任务有稳定编号，例如 `T-1A`，私聊时可使用短形式 `1A`。
- 私聊自然语言支持完成、取消、延期、标题修改、负责人调整和误识别撤销。
- 任务卡片支持完成、取消和日期选择延期。
- 多人共同任务只创建一条任务；每位负责人收到同一编号的私聊通知。
- 新任务进入 `todo` 后立即私聊每位负责人；`pending` 审核前保持静默。
- 负责人完成、取消或延期后，其他共同负责人和本群管理员按既有去重规则收到
  私聊通知。

### Phase 7A–7C：管理后台与群管理员

- 飞书私聊“管理后台”生成一次性登录链接，并使用 HttpOnly 会话鉴权。
- 页面只展示当前用户有权管理的群，并记住当前选中的群。
- 群主可在群内初始化或接管本群；管理员可在后台授予或撤销其他当前群成员。
- 每群至少保留一名管理员；群成员离群后自动撤权并使无权限会话失效。
- 多管理员场景下，管理员通知默认发给全部管理员，并跳过没有信息增量的操作人
  自我通知。

### Phase 7D-1–7D-4A：后台任务维护

- 管理员可修改截止时间、标题和有序的多人负责人列表。
- 管理员可明确完成、取消或撤销误识别任务。
- 管理后台提供任务状态筛选、证据消息、生命周期和投递记录。
- `pending` 任务有独立“待审核”入口。
- 管理员确认后执行 `pending → todo`，原子生成负责人私聊和截止提醒。
- 管理员判定误识别后执行 `pending → cancelled`，不生成负责人新任务通知或截止
  提醒，并保留审核审计。
- `confirm` 仅允许管理后台管理员执行，不开放给 LLM、普通私聊命令或任务卡片。
