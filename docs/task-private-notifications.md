# 任务私聊通知

## 新任务分配通知

从迁移 `20260823_0021` 起，自动物化为 `todo` 的新任务会在创建事务内为每位
负责人写入一条 `task_created_assignee` 私聊通知。通知包含稳定任务编号、标题、
全部负责人和截止时间，并提示负责人可发送“任务列表”或直接用任务编号更新。

低置信度 `pending` 任务不会通知负责人；若后续证据或本群管理员审核把它晋升
为 `todo`，系统才发送一次分配通知。共享任务每位负责人各收到一条，同一物化、
晋升或审核操作可安全重放而不会重复入队。通知严格私聊，失败时按持久化队列
重试，不回退到群聊。

新通知只在未来任务创建或晋升时原子入队，不扫描和补发历史任务，避免功能上线
时打扰已有任务负责人。

## 行为规则

`task-notification-worker` 负责截止日缺失追问和管理员状态通知。它与
普通的截止日提醒 Worker 分离，两者均使用持久化队列。

| 条件 | 接收人 | 正式时间 | 测试时间 |
| --- | --- | --- | --- |
| 新任务进入 `todo` | 每位负责人 | 立即 | 立即 |
| `todo` 且无截止时间 | 负责人 | 创建后 1 天 | 创建后 2 分钟 |
| 仍为 `todo` 且无截止时间 | 管理员 | 创建后 3 天 | 创建后 4 分钟 |
| 负责人完成任务 | 管理员 | 立即 | 立即 |
| 负责人取消任务 | 管理员 | 立即 | 立即 |
| 负责人延期任务 | 管理员 | 立即 | 立即 |
| 任务进入 `overdue` | 管理员 | 立即 | 立即 |
| 共同任务被完成、取消或延期 | 其他共同负责人 | 立即 | 立即 |

管理员收到第二级无截止时间提示后，机器人不再就该任务追问。提示
前如果设置了截止时间，或任务已完成、取消，未发送的缺失截止时间通知
会被取消。

完成、取消和延期通知来自已通过权限校验并原子写入的生命周期事件。延期
通知保留原、新截止时间。如果操作人
本身就是管理员，不向其发送没有信息增量的自我通知。

## 发送与可靠性

- 所有通知只私聊，私聊发送失败时不降级为群消息。
- 如果成员曾私聊过机器人，优先使用已知私聊 `chat_id`；否则用 Open ID
  创建私聊消息。
- 数据库唯一键防止同一任务事件向同一接收人重复发送。
- 失败通知按 Worker 的重试和租约规则重试；每次尝试、飞书消息 ID 和
  最后错误均留在 `task_notifications`。
- 迁移 `20260823_0013` 用持久游标跳过升级前的历史完成/取消事件，
  不会在上线时补发旧通知。

## 运行

```bash
python -m app task-notification-worker --forever
```

单次调试：

```bash
python -m app task-notification-worker --once
```

时间缩短开关与普通提醒共用 `REMINDER_TEST_MODE`。正式部署必须设为
`false`。
